# DP_TextFile_Sorter — семантический сортировщик Markdown-заметок Obsidian

Программа раскладывает копии `.md`-заметок по **уже существующей** структуре каталогов
хранилища. Структура папок пользователя — это его система категорий; программа не
придумывает новые категории, а учится понимать имеющиеся и распределяет заметки по ним.

```
Существующая структура каталогов  →  система категорий
                                  ↓
                        анализ Markdown-файла
                                  ↓
                       семантическое сравнение
                                  ↓
                    наиболее подходящая категория
                                  ↓
        Sorted_md_files/<категория>/<файл>.md   (копия, оригинал не тронут)
```

**Приоритеты:** сохранность исходных файлов → корректность классификации →
предсказуемость → проверяемость → повторяемость → расширяемость → производительность.

## Быстрый старт

```bash
# 1. Перейти в каталог хранилища (INBOX)
cd ~/Obsidian/INBOX

# 2. Посмотреть, что программа собирается сделать — ничего не изменяя
python /путь/к/sorter.py --dry-run

# 3. Если результат устраивает — выполнить сортировку
python /путь/к/sorter.py
```

Корневым каталогом считается **текущий каталог запуска**, а не расположение скрипта.
Явно задать его можно через `--root`.

После работы исходные `.md` остаются на своих местах, а их копии появляются в
`Sorted_md_files/` внутри хранилища.

## Установка и зависимости

**Базовая версия не требует ничего, кроме Python 3.11+.** Ни одной внешней библиотеки.
Это сделано намеренно: программа должна запускаться в том числе в Termux на Android.

```bash
python --version   # нужен 3.11 или новее (используется tomllib)
python sorter.py --help
```

| Файл | Что ставит | Когда нужен |
|---|---|---|
| `requirements.txt` | ничего | базовый режим `--classifier lexical` |
| `requirements-optional.txt` | `scikit-learn`, `sentence-transformers`, `anthropic`, `PyYAML` | альтернативные классификаторы |
| `requirements-dev.txt` | `pytest` | запуск тестов |

Опциональные зависимости ставятся по одной, по мере необходимости:

```bash
pip install scikit-learn          # --classifier tfidf
pip install sentence-transformers # --classifier embeddings, --classifier hybrid
pip install anthropic             # --classifier llm  (нужен ANTHROPIC_API_KEY)
pip install PyYAML                # более строгий разбор frontmatter (не обязателен)
```

Проверено на Linux, Windows и Termux/Android. Абсолютных путей в коде нет,
все пути строятся через `pathlib`.

### Termux / Android

```bash
pkg update && pkg upgrade
pkg install python
termux-setup-storage          # разрешить доступ к /sdcard

cd /sdcard/MAIN_OBSIDIAN_PC
python /storage/emulated/0/CODE/PYTHON/DP_Obsdian_Sorter/sorter.py --dry-run
```

Хранилище на `/sdcard` смонтировано через FUSE: там запрещены `chmod` и `utime`,
не работают символические ссылки, а имена файлов подчиняются ограничениям FAT.
Программа это учитывает — содержимое копируется, а перенос прав и времени
изменения выполняется по возможности и не считается ошибкой.

Если `python` отвечает `Permission denied`, интерпретатор не установлен или
найден на разделе, смонтированном с `noexec`. Проверить:

```bash
command -v python && ls -l "$(command -v python)" && echo "$PATH"
```

Путь должен указывать в `/data/data/com.termux/files/usr/bin`, а не в `/sdcard`.

## Алгоритм классификации

### 1. Что извлекается из заметки

| Признак | Вес | Примечание |
|---|---|---|
| имя файла | 3.0 | «сильный» признак |
| теги frontmatter и инлайн-теги `#python`, `#linux/arch` | 3.0 | «сильный» |
| `aliases`, `category`, `type` из frontmatter | 3.0 | «сильный» |
| заголовок H1 | 2.5 | «сильный» |
| заголовки H2–H3 | 2.0 | «сильный» |
| язык кодового блока (` ```python `) | 2.5 | «сильный» |
| `[[wiki-links]]` | 1.5 | «сильный» |
| содержимое кодовых блоков (импорты, команды) | 1.5 | |
| исходный каталог заметки | 1.0 | плюс отдельный бонус |
| основной текст и списки | 1.0 | |

«Сильные» признаки собираются в отдельный вектор — по нему делается второй проход
(см. пункт 3), чтобы длинная проза не размывала однозначный сигнал вроде `tags: [minecraft]`.

### 2. Что известно о категории

Профиль каталога складывается из:

1. **имени** каталога (вес 3.0) — `Dev-Tools` → `dev`, `tools`;
2. **полного пути** (вес 2.0) — `Linux/Termux` даёт и `linux`, и `termux`, поэтому
   каталог читается как «Linux → Termux», а не просто «Termux»;
3. **встроенного словаря** (`lexicon.py`) — `arch` → `pacman`, `aur`, `yay`, …;
   термины в списке идут от самого характерного, вес убывает как `1/√i`, а масса
   всего блока растёт как `√N`, чтобы длинный список синонимов не размывал вектор;
4. **пользовательских алиасов** из `md_sorter.toml` — способ подстроить программу
   под своё хранилище без правки кода;
5. **заметок, которые уже лежат в этом каталоге** — лучшее описание категории.
   Вклад делится на `√N` и ограничен сверху массой собственных признаков категории;
   при оценке заметки её собственный вклад из профиля вычитается, иначе каталог
   с одной заметкой превратился бы в детектор её копий.

### 3. Как считается оценка

```
similarity = max( cosine(вектор_всей_заметки,  вектор_категории),
                  cosine(вектор_сильных_признаков, вектор_категории) )

score      = similarity
           + 0.35 · similarity(родительской категории)      # поддержка родителя
           × 1.15  если имя категории есть в сильных признаках
           + 0.10  если заметка уже лежала в этом каталоге
           × (1 + 0.06 · (глубина − 1))                     # бонус за конкретность
```

Векторы разреженные, взвешенные по IDF (считается по всему хранилищу);
сравнение со всеми категориями выполняется за один проход по инвертированному индексу.

**Правило потомка.** Если лидер является предком другого сильного кандидата и разрыв
между ними не больше 10 %, побеждает потомок. Поэтому при наличии `Linux`, `Linux/Arch`
и `Linux/Termux` заметка про Arch попадает именно в `Linux/Arch`.

### 4. Когда решение считается сомнительным

- лучшая оценка ниже `threshold` (по умолчанию `0.22`);
- разрыв между первым и вторым местом меньше `margin` (`0.06`), и кандидаты **не**
  связаны отношением предок/потомок;
- в структуре вообще нет каталогов назначения.

Если два спорных кандидата — соседи с общим родителем, и родитель сам проходит порог,
заметка кладётся **в родителя** (`Linux` вместо спора `Arch` ↔ `Termux`).

Иначе применяется стратегия `--uncertain-strategy`:

| Стратегия | Поведение |
|---|---|
| `review` (по умолчанию) | `Sorted_md_files/_NEEDS_REVIEW/` |
| `ancestor` | ближайший общий предок кандидатов, иначе `_NEEDS_REVIEW` |
| `root` | корень `Sorted_md_files/` |
| `skip` | не копировать, только сообщить |

`_NEEDS_REVIEW` создаётся только внутри `Sorted_md_files`, никогда в исходном
хранилище, и не участвует в классификации как категория.

## Параметры командной строки

```
python sorter.py [--root PATH] [--dry-run] [-v] [--debug] [-q] [--log-file PATH]
                 [--color | --no-color]
                 [--classifier {lexical,tfidf,embeddings,llm,hybrid}]
                 [--threshold FLOAT] [--margin FLOAT]
                 [--uncertain-strategy {review,ancestor,root,skip}]
                 [--top-candidates N] [--embedding-model NAME]
                 [--ignore DIR] [--include-hidden] [--follow-symlinks]
                 [--max-file-size BYTES] [--max-analysis-chars N] [--jobs N]
                 [--manifest | --no-manifest] [--move] [--allow-move]
                 [--config PATH] [--no-config]
```

Полный список с описаниями: `python sorter.py --help`.

Часто нужное:

```bash
python sorter.py --dry-run                        # предварительный просмотр
python sorter.py --verbose                        # с объяснением решений
python sorter.py --threshold 0.35                 # строже: больше в _NEEDS_REVIEW
python sorter.py --uncertain-strategy ancestor    # спорное — в общего предка
python sorter.py --log-file sort.log              # лог ещё и в файл
python sorter.py --jobs 0                         # многопроцессный разбор
python sorter.py --manifest                       # вести файл состояния
```

## Конфигурация

Файл `md_sorter.toml` (или `.md_sorter.toml`) в корне хранилища. Полный пример —
`md_sorter.example.toml`. Все параметры необязательны, аргументы CLI имеют приоритет.

```toml
[md_sorter]
threshold = 0.22
uncertain_strategy = "review"
classifier = "lexical"
manifest = false

# Главный инструмент подстройки под своё хранилище: характерные слова категорий.
[md_sorter.aliases]
"Linux/Termux" = ["термукс", "телефон", "pkg", "proot"]
"Hobby/Moto" = ["мотоцикл", "цепь", "масло", "пробег"]
```

`--no-config` полностью игнорирует файл конфигурации.

## Гарантии безопасности

1. **Исходные файлы открываются только на чтение.** Ни одной операции записи за
   пределами `ROOT/Sorted_md_files/`.
2. **Режим по умолчанию — COPY.** `--move` заблокирован без явного `--allow-move`.
3. **Программа ничего не удаляет.** Существующий `Sorted_md_files` не очищается.
4. **Атомарная запись.** Имя резервируется через `O_EXCL`, данные пишутся во временный
   файл и переименовываются поверх — прерывание не оставит полуфайл.
5. **Запуск внутри `Sorted_md_files` запрещён** — иначе результат сортировался бы повторно.
6. **`--dry-run` не создаёт ни каталогов, ни файлов, ни манифеста.**

Проблемные файлы не роняют программу — ошибка попадает в лог, обработка продолжается:

| Случай | Поведение |
|---|---|
| символические ссылки | пропускаются, `--follow-symlinks` включает (с защитой от циклов) |
| скрытые файлы и каталоги | пропускаются, `--include-hidden` включает |
| нет прав на чтение | `[ERROR]`, счётчик ошибок, продолжаем |
| битая кодировка | анализируется с заменой символов, копируется побайтово без изменений |
| файл больше `max_file_size` | анализируется начало, `[WARNING]`, копируется целиком |
| пустой файл | классифицируется по имени и пути |
| не обычный файл (FIFO, сокет) | пропускается |
| файл исчез между сканированием и копированием | `[ERROR]`, продолжаем |

## Повторные запуски

Программа рассчитана на многократный запуск.

- `Sorted_md_files` **всегда** исключён из поиска — на трёх независимых рубежах
  (обрезка ветки по резолвнутому пути, пост-фильтр, проверка корня при старте).
  `Sorted_md_files/Sorted_md_files` создать невозможно.
- Если копия уже существует и **совпадает по SHA-256** — копирование пропускается.
  Поэтому второй запуск не порождает дублей и оставляет дерево неизменным.
- Если исходник изменился, старая копия **не перезаписывается**: рядом появляется
  `note_1.md`. Ничего не теряется, разбирается вручную.
- Файл состояния `Sorted_md_files/.md_sorter_manifest.json` (**только при `--manifest`**)
  позволяет пропускать неизменившиеся файлы без чтения их содержимого. Идемпотентность
  работает и без него — за счёт сверки хэшей.

## Замена алгоритма классификации

Все классификаторы реализуют один интерфейс `md_sorter/classifier/base.py`:

```python
class Classifier(ABC):
    def fit(self, notes, categories, notes_by_category=None) -> None: ...
    def rank(self, note, note_index=-1) -> list[Candidate]: ...
    def close(self) -> None: ...
```

Готовые варианты:

```bash
python sorter.py --classifier lexical      # по умолчанию, без зависимостей
python sorter.py --classifier tfidf        # scikit-learn
python sorter.py --classifier embeddings   # sentence-transformers, работает офлайн
python sorter.py --classifier hybrid       # 0.4 · lexical + 0.6 · embeddings
python sorter.py --classifier llm          # Claude API как арбитр
```

### Как добавить свой

Подклассы `LexicalClassifier` переопределяют **только** способ расчёта близости —
правила иерархии (поддержка родителя, бонус за конкретность, правило потомка) и
формирование объяснений наследуются:

```python
# md_sorter/classifier/my_model.py
from .lexical import LexicalClassifier


class MyClassifier(LexicalClassifier):
    name = "my-model"

    def fit(self, notes, categories, notes_by_category=None):
        super().fit(notes, categories, notes_by_category)
        self._model = load_my_model()
        self._category_vectors = self._model.encode([c.key for c in categories])

    def _base_scores(self, note, note_index, note_vector):
        """Возвращает список оценок 0..1 — по одной на каждую категорию."""
        embedding = self._model.encode(note.title or note.record.stem)
        return [float(similarity(embedding, vec)) for vec in self._category_vectors]
```

Регистрация в `md_sorter/classifier/__init__.py`:

```python
def _make_my_model(config):
    from .my_model import MyClassifier
    return MyClassifier(config)


_FACTORIES["my-model"] = _make_my_model
```

После этого `--classifier my-model` доступен, а `--help` подхватит новое имя
автоматически. Если модель принципиально другая, наследуйтесь напрямую от
`Classifier` и реализуйте `rank()` целиком.

### Классификаторы с внешними сервисами

`--classifier llm` не отправляет модели всё хранилище: лексический алгоритм отбирает
короткий список кандидатов (`llm_shortlist`, по умолчанию 10), и модель выбирает из
него. Это ограничивает объём запроса и стоимость независимо от размера хранилища.
При любой ошибке сети или отсутствии ключа программа молча возвращается к локальному
алгоритму и продолжает работу.

## Производительность

Замер на этой машине (Python 3.11, один процесс, `--dry-run`):

| Заметок | Время | Пик памяти |
|---|---|---|
| 5000 | 2.5 с | 56 МБ |

Что для этого сделано:

- каждый файл читается **ровно один раз**; сырой текст не хранится — в памяти живут
  компактные мешки токенов;
- обход через `os.scandir` с обрезкой веток до входа в них;
- IDF считается за один проход, векторы категорий строятся один раз;
- сравнение со всеми категориями — один проход по инвертированному индексу, а не цикл
  по каждой категории;
- анализируется не более `max_analysis_chars` символов заметки;
- `--jobs 0` включает многопроцессный разбор (автоматически при большом числе файлов);
  при недоступности `multiprocessing` (бывает в Termux) происходит откат в один поток;
- для `--classifier embeddings` — кэш по SHA-256 текста в
  `Sorted_md_files/.cache/embeddings.json`.

## Ограничения и дальнейшее развитие

**Что алгоритм делает плохо (честно):**

- Лексический классификатор сравнивает слова, а не смыслы. Заметка про Doom,
  написанная по-русски без единого узнаваемого термина, может не найти категорию —
  для таких случаев есть `--classifier embeddings`.
- Оценки зависят от размера хранилища: IDF считается по корпусу, поэтому на пяти
  заметках уверенность ниже, чем на пятистах. Порог при необходимости меняется
  через `--threshold`.
- Русская морфология обрабатывается стеммером Snowball: `секреты` ≈ `секрет`, но
  `уровни` ≠ `уровень` (беглые гласные алгоритму не поддаются).

**Что напрашивается дальше:**

- интерактивный разбор `_NEEDS_REVIEW` (`--interactive`);
- отчёт в JSON/CSV для внешней оценки качества классификации;
- предложение новых категорий по кластерам «непонятых» заметок — строго как отчёт,
  без автосоздания каталогов;
- режим наблюдения за каталогом и git-hook;
- упаковка в `pyproject.toml` с консольной командой `md-sorter`.
